# 常见问题（FAQ）

## 安装与运行

**Q1：计划任务显示就绪但就是不运行？**
- 确认任务是"最高权限"、触发器是"登录时"。
- 确认 `guardian.ps1` 路径正确、文件确实存在。
- **确认脚本是 UTF-8 with BOM**：Windows PowerShell 5.1 会用 GBK 解析无 BOM 的脚本，中文注释会让它报 `The string is missing the terminator` 之类的语法错误，任务结果 1 且日志里什么都没有。
- 手动执行一次看是否报错：
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File "完整路径\guardian.ps1"
  ```

**Q2：提示 PowerShell 执行策略 / 脚本被禁止运行？**
- 安装器已使用 `-ExecutionPolicy Bypass`，正常情况下不会拦截。
- 也可放开当前用户执行策略：
  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```

**Q3：守护脚本启动后立刻退出？**
- 用上面的命令手动执行，看红色报错；通常是配置区路径填错或 token 不对。

**Q4：怎么安全地重启守护脚本（改完配置后）？**
```powershell
Stop-ScheduledTask -TaskName NapCatGuardian
Start-ScheduledTask -TaskName NapCatGuardian
```
这两个命令在**普通权限**下就能用（只有注册任务才需要管理员）。它只结束守护脚本自身，不会杀掉 NapCat / QQ。

## 保活

**Q5：日志里没有 `keep-alive sent`？**
- 守护脚本只在**当前在线**、且**距上次真实收发已满 10 分钟**时才发探针；有人正在聊天时不会发。
- 想立刻验证，临时把 `$KEEPALIVE_MIN` 和 `$KEEPALIVE_IDLE_MIN` 都调小（例如 60 秒 / 0 分钟）再重启任务。

**Q6：保活消息返回的不是 `retcode=0`？**
- 注意：**连接已经死掉时 `retcode` 也可能仍是 200**。真正的判据是响应体的 `status` 字段（`ok` / `failed`）和 `message` 里有没有 `1006514 网络连接异常`。`Confirm-SendBroken` 现在直接看这个字段，不再依赖日志延迟。
- 确认 `user_id` 填的是**机器人自己**的 QQ 号。
- 先手动给任意好友发一条消息，确认 NapCat 消息能力正常。

**Q7：保活消息会不会浪费模型 token？**
- 不会。发给自己的消息在 AstrBot 的 `waking_check` 阶段就被拦掉，不进入 LLM；只要你的 `wake_prefix` 不是空串（默认 `//`），且保活文本里不带它。

## 恢复

**Q8：开机后 AstrBot 起来了，NapCat 却没自动启动 / 没上线？**
- 新版检测到 WebUI(6099) 连不上（NapCat 根本没运行）时会**立即启动**，不再空等。确认用的是本仓库最新 `guardian.ps1`。
- 如果启动后提示"身份已失效"，说明快速登录凭证过期，需扫码一次（会自动弹窗 + 写 `login-state.json`）。

**Q9：网络一波动，守护脚本就把 QQ 杀了？**
- 新版先给 90 秒宽限期；另外"发送失败探测"会在连接真的死掉时只重启 worker（不杀 QQ）。确认用的是最新 `guardian.ps1`。

**Q10：为什么现在很少自动重启了？是不是坏了？**
- 这是刻意设计。`$MAX_RECOVER = 1` + 120 分钟熔断：一次掉线只自动救一次，失败就停手等人。频繁重启会形成连续无效登录尝试，是触发风控/冻结的主要信号。
- 日志里会明确写 `Recovery attempt #1 failed - opening 120 min circuit`，不是卡死。

**Q11：每次恢复都要扫码？**
- 说明快速登录凭证已经失效（常见于被反复强杀、长时间掉线、同号在手机端同时在线）。
- 先正常扫码登录并保持一段时间刷新凭证；之后避免强杀 QQ。

**Q12：日志里 `isLogin=True` 但收不到消息？**
- 这是**僵死态**。守护脚本会通过 `CheckLoginStatus.loginError` 和发送失败探测识别它，自动 `RestartNapCat` 用缓存 token 登回，一般不需要扫码。

**Q13：失败弹窗（msg.exe）不出现？**
- 部分 Windows 家庭版 / 精简版没有 `msg.exe`。可改用其它通知：发邮件、Server 酱、企业微信 / 钉钉机器人，或直接读 `login-state.json` 做个小网页。

**Q14：AstrBot 没被自动拉起来？**
- AstrBot 由 `scripts/runtime/astrbot_watchdog.ps1` 独立看护（**普通权限**运行），不由 guardian 启动。
- 检查脚本里的 `$ASTRBOT_DIR` 下是否有 `main.py`、`$PYTHON` 是否正确；进目录手动 `python main.py` 先解决它自身的报错。

**Q15：关掉控制台窗口，机器人就死了？**
- v2 的所有拉起动作都用 `CreateNoWindow`，窗口根本不会出现，关窗口也就谈不上"连带杀死"。
- 如果你还看到残留窗口，多半是旧版脚本用 `Start-Process cmd -WindowStyle Minimized` 起的进程，换新版并重启任务即可。

## 网络与账号

**Q16：用 WiFi 还是网线？**
- 长期挂机强烈建议**网线**；WiFi 的省电、干扰、漫游都会造成短暂断流。

**Q17：network_fix.ps1 执行后网络断了？**
- 脚本会重启网卡，断网几秒到十几秒属正常，会自动恢复。

**Q18：频繁被 `KickedOffLine` 踢下线怎么办？**
- 先排除**同号多端在线**：手机 QQ 的「切换账号」**不等于退出登录**，小号会话仍在后台，服务端会认为 PC 侧"登录态已失效"。用完请在小号界面**退出登录**。
- 其次保持 NapCat 为新版、QQ 为官方推荐版本（老 NapCat 会被判为外挂强制下线）。
- 开通会员**不能**防风控；风控看设备指纹、登录地、行为模式。
- 别把保活间隔调得太短，也不要让守护脚本反复重启。

**Q19：桌面 QQ 一开，机器人就掉？**
- 两者共用 `%APPDATA%\QQ`，Electron 单实例锁互踢。设置 `$QQ_DATA_DIR`（即 `NAPCAT_QQ_DATA_DIR`）隔离数据目录，代价是切换时扫码一次。

## 安全

**Q20：把配置发到 GitHub 会不会泄露信息？**
- 仓库里的示例都是**脱敏占位**，没有真实 QQ 号 / 密钥。新版的 `guardian.ps1` 也已把 `$QQ_UIN`、`$WEBUI_TOK` 换成 `YOUR_BOT_QQ` / `YOUR_WEBUI_TOKEN`。
- 你自己的脚本与 `cmd_config.json` 含真实信息，**不要直接提交**；建议用 `.gitignore` 排除，或只提交 `.example` 版本。

**Q21：本地 API 要对外暴露吗？**
- 不要。本地 API 绑定 `127.0.0.1` 即可，否则可能被他人调用。

## 其它

**Q22：如何查看守护日志？**
- 查看 `guardian.ps1` 里 `$LOG_FILE` 指向的文件，默认 `D:\napcat\guardian.log`。

**Q23：如何彻底停止守护？**
```powershell
Unregister-ScheduledTask -TaskName NapCatGuardian -Confirm:$false
```

**Q24：手机收到的中文通知变成了 `?`？**
- 发送端编码问题。Windows PowerShell 5.1 的 `Invoke-RestMethod` / `Invoke-WebRequest` 在 `-Body` 传**字符串**时会按 ASCII 编码，一个汉字换一个 `?`；只加 `-ContentType 'text/plain'` 也不算修好，必须声明 charset 并传字节：

  ```powershell
  $bytes = [System.Text.Encoding]::UTF8.GetBytes($body)
  Invoke-RestMethod -Uri $url -Method Post -Body $bytes -ContentType 'text/plain; charset=utf-8'
  ```

- ntfy 的 `Title` 请求头只能放 ASCII，中文标题需转 RFC 2047（`=?UTF-8?B?<base64>?=`），本仓库已内置 `ConvertTo-NtfyHeaderText`。
- 验证方法：把收到的那条翻回去看，`Content-Length` 应该**大于**汉字字符数（UTF-8 下汉字 3 字节）。

**Q25：AstrBot 启动日志一直刷「等待 Provider 就绪（未就绪: Embedding Provider）」？**
- livingmemory 没配 embedding 模型时会重试 60 次后放弃，记忆向量功能实际不可用（不影响主流程，但白等几分钟）。
- 配一个即可（DashScope `text-embedding-v4` 便宜且够用）。关键点：**必须显式写 `embedding_dimensions`**，否则报 `无效的嵌入向量维度: 0`：

```json
{
  "id": "dashscope_embedding",
  "type": "dashscope_embedding",
  "provider_type": "embedding",
  "provider": "dashscope",
  "embedding_api_key": "你的 key",
  "embedding_api_base": "https://dashscope.aliyuncs.com/api/v1",
  "embedding_model": "text-embedding-v4",
  "embedding_dimensions": 1024,
  "enable": true
}
```

- 原因：适配器的 `get_dim()` 直接读这个字段，不会去探测模型真实维度。

**Q26：AstrBot 的 6185 面板能不能从别的机器打开？**
- 默认可以（`dashboard.host` 是 `0.0.0.0`），但不建议：等于把管理面板暴露给整个局域网/VPN。
- 改成 `127.0.0.1` 后重启 AstrBot；需要远程时用 SSH 隧道或临时反代，别长期开着。
**Q27：为什么"被踢"之后不先试快速登录，而是直接全量重启？**
- 2026-11-15 实测 14 次被踢：进程内 `SetQuickLogin` 全部失败，`RestartNapCat` 之后页面上只剩二维码（`isLogin=false`、`loginError` 为空），票据并没有被复用。
- 而完整重启（杀 QQ → launcher）在票据仍有效时能自己登回来（`logged in.`，无需扫码）。
- 所以现在的顺序是：`[KickedOffLine]` → 跳过 A/B/C → 直接全量重启。少花 10 分钟，也少两次注定失败的登录尝试（无效登录尝试本身是风控信号）。

**Q28：为什么会有"主动续期"的开关，但默认是关的？**
- 14 次被踢的会话存活时长中位 117 分钟、10/14 落在 109–121，看起来像票据约 2 小时过期，于是加过"活满 100 分钟主动 `RestartNapCat` 续期"。
- 实测这条路会强制扫码（worker 重启不复用票据），比被踢更糟，所以 `$PROACTIVE_REFRESH_MIN` 默认 `0`。如果以后 NapCat 版本改变了这个行为，可以把它设成 `100` 再试。

**Q29：机器人到底多久被踢一次？怎么看？**
- 看 `kick.log`（每次真实被踢一行，带 `at=`、`session=`、`quiet_before_kick=`、`ip=`）和 `metrics.json` 里的 `kicksToday` / `lastKick`。
- 注意 `kicksToday` 只统计真实 `[KickedOffLine]`，不含"假在线"（`1006514`）和网络抖动 —— 后者是另一类事件，混在一起会高估。

**Q30：固定域名怎么突然变成了 `xxx.trycloudflare.com`？**
- 说明 ngrok 那一步失败了、守护退到了 cloudflare 快速隧道。最常见原因是**上一个 ngrok 进程还挂着同一个固定域名**（守护被停掉时 `Stop-ScheduledTask` 不会杀掉孙进程），新进程报 `ERR_NGROK_334 ... is already online` 后退出。
- `daemon.ps1` 现在会识别这个错误：自动结束占着该域名的残留 `ngrok.exe` 再重试一次，日志里会出现「固定域名被残留的 ngrok 进程占用，清理后重试 / 已结束残留 ngrok PID …」。
- 如果手动确认，`Get-Process ngrok` 后结束掉旧进程、重启 `QRSyncDaemon` 即可；`current-url.txt` 会写回固定域名。

**Q31：扫码页会不会在我不知道的时候挂掉？**
- `daemon.ps1` 每次公网自检都会写 `qrsync\tunnel-state.json`（`ok` / `provider` / `url` / `failStreak` / `at`）。
- 看护读到 `ok=false` 且该状态超过 `$TUNNEL_ALERT_MIN`（默认 10 分钟），就发一封「NapCat QR page unreachable」邮件（60 分钟冷却），因为扫码页是唯一的远程自救通道。
- `status.ps1` 的「扫码通道」一行也能直接看到当前隧道供应商与自检时间。
