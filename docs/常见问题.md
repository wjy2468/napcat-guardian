# 常见问题（FAQ）

## 安装与运行

**Q1：计划任务显示就绪但就是不运行？**
- 确认任务是"最高权限"、触发器是"登录时"。
- 确认 `guardian.ps1` 路径正确、文件确实存在。
- 手动执行一次看是否报错：
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File "完整路径\guardian.ps1"
  ```

**Q2：提示 PowerShell 执行策略 / 脚本被禁止运行？**
- 安装器已使用 `-ExecutionPolicy Bypass`，正常情况下不会拦截。
- 也可放开当前用户执行策略：
  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```

**Q3：守护脚本启动后立刻退出？**
- 用上面的命令手动执行，看红色报错；通常是配置区路径填错或 token 不对。

## 保活

**Q4：日志里没有 `keep-alive sent`？**
- 守护脚本只在**当前在线**时才发保活；先确认机器人在线。
- 等待一个保活周期（10–17 分钟），或临时把 `$KEEPALIVE_MIN` 调小测试。

**Q5：保活消息返回的不是 `retcode=0`？**
- 确认 `user_id` 填的是**机器人自己**的 QQ 号。
- 先手动给任意好友发一条消息，确认 NapCat 消息能力正常。

**Q6：还是会被踢？**
- 确认保活间隔明显小于被踢阈值（23 分钟）；可把区间调到 8–13 分钟。
- 确认走的是"发消息"而不是"调本地 API"。
- 用 `guardian.log` 里的时间核对保活是否真的在发。

## 恢复

**Q7：网络一波动，守护脚本就把 QQ 杀了？**
- 新版已在最前面加了 90 秒宽限期。确认你用的是本仓库最新 `guardian.ps1`。

**Q8：每次恢复都要扫码？**
- 说明快速登录凭证已经失效（常见于被反复强杀、长时间掉线）。
- 先正常扫码登录一次并保持一段时间，让凭证刷新；之后尽量避免强杀 QQ。

**Q9：失败弹窗（msg.exe）不出现？**
- 部分 Windows 家庭版 / 精简版没有 `msg.exe`。
- 可自行替换为其它通知：发邮件、Server 酱、企业微信 / 钉钉机器人等。

**Q10：AstrBot 没被自动拉起来？**
- 检查 `$ASTRBOT_DIR` 下是否有 `main.py`、`$PYTHON_EXE` 路径是否正确。
- 进入目录手动执行 `python main.py`，先解决它自身的报错。

## 网络

**Q11：用 WiFi 还是网线？**
- 长期挂机强烈建议**网线**，WiFi 的省电、干扰、漫游都会造成短暂断流。

**Q12：network_fix.ps1 执行后网络断了？**
- 脚本会重启网卡，断网几秒到十几秒属正常，会自动恢复。

## 安全

**Q13：把配置发到 GitHub 会不会泄露信息？**
- 仓库里的示例都是**脱敏占位**，没有任何真实 QQ 号 / 密钥。
- 你自己的 `guardian.ps1`、`cmd_config.json` 含真实信息，**不要直接提交**；建议用 `.gitignore` 排除，或只提交 `.example` 版本。

**Q14：本地 API 要对外暴露吗？**
- 不要。本地 API 绑定 `127.0.0.1` 即可，否则可能被他人调用。

## 其它

**Q15：如何查看守护日志？**
- 查看 `guardian.ps1` 里 `$LOG_FILE` 指向的文件，默认 `D:\napcat\guardian.log`。

**Q16：如何彻底停止守护？**
```powershell
Unregister-ScheduledTask -TaskName NapCatGuardian -Confirm:$false
```
