# 常见问题（FAQ）

## 安装与运行

**Q1：计划任务显示就绪但就是不运行？**
- 确认任务是"最高权限"、触发器是"登录时"。
- 确认 `guardian.ps1` 路径正确、文件确实存在。
- **确认脚本是 UTF-8 with BOM**：Windows PowerShell 5.1 会用 GBK 解析无 BOM 的脚本，中文注释会让它报 `The string is missing the terminator` 之类的语法错误，任务结果 1 且日志里什么都没有。
- 手动执行一次看是否报错：
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File "完整路径\guardian.ps1"
  ```

**Q2：提示 PowerShell 执行策略 / 脚本被禁止运行？**
- 安装器已使用 `-ExecutionPolicy Bypass`，正常情况下不会拦截。
- 也可放开当前用户执行策略：
  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```

**Q3：守护脚本启动后立刻退出？**
- 用上面的命令手动执行，看红色报错；通常是配置区路径填错或 token 不对。

**Q4：怎么安全地重启守护脚本（改完配置后）？**
```powershell
Stop-ScheduledTask -TaskName NapCatGuardian
Start-ScheduledTask -TaskName NapCatGuardian
```
这两个命令在**普通权限**下就能用（只有注册任务才需要管理员）。它只结束守护脚本自身，不会杀掉 NapCat / QQ。

## 保活

**Q5：日志里没有 `keep-alive sent`？**
- 守护脚本只在**当前在线**时才发保活；先确认机器人在线。
- 默认间隔 30–45 分钟，等一个周期，或临时把 `$KEEPALIVE_MIN` 调到 60 秒测试。

**Q6：保活消息返回的不是 `retcode=0`？**
- 确认 `user_id` 填的是**机器人自己**的 QQ 号。
- 先手动给任意好友发一条消息，确认 NapCat 消息能力正常。
- 非 0 的 `retcode` 本身就是"连接已死"的信号，守护脚本会据此触发恢复。

**Q7：保活消息会不会浪费模型 token？**
- 不会。发给自己的消息在 AstrBot 的 `waking_check` 阶段就被拦掉，不进入 LLM；只要你的 `wake_prefix` 不是空串（默认 `//`），且保活文本里不带它。

## 恢复

**Q8：开机后 AstrBot 起来了，NapCat 却没自动启动 / 没上线？**
- 新版检测到 WebUI(6099) 连不上（NapCat 根本没运行）时会**立即启动**，不再空等。确认用的是本仓库最新 `guardian.ps1`。
- 如果启动后提示"身份已失效"，说明快速登录凭证过期，需扫码一次（会自动弹窗 + 写 `login-state.json`）。

**Q9：网络一波动，守护脚本就把 QQ 杀了？**
- 新版先给 90 秒宽限期；另外"发送失败探测"会在连接真的死掉时只重启 worker（不杀 QQ）。确认用的是最新 `guardian.ps1`。

**Q10：为什么现在很少自动重启了？是不是坏了？**
- 这是刻意设计。`$MAX_RECOVER = 1` + 120 分钟熔断：一次掉线只自动救一次，失败就停手等人。频繁重启会形成连续无效登录尝试，是触发风控/冻结的主要信号。
- 日志里会明确写 `Recovery attempt #1 failed - opening 120 min circuit`，不是卡死。

**Q11：每次恢复都要扫码？**
- 说明快速登录凭证已经失效（常见于被反复强杀、长时间掉线、同号在手机端同时在线）。
- 先正常扫码登录并保持一段时间刷新凭证；之后避免强杀 QQ。

**Q12：日志里 `isLogin=True` 但收不到消息？**
- 这是**僵死态**。守护脚本会通过 `CheckLoginStatus.loginError` 和发送失败探测识别它，自动 `RestartNapCat` 用缓存 token 登回，一般不需要扫码。

**Q13：失败弹窗（msg.exe）不出现？**
- 部分 Windows 家庭版 / 精简版没有 `msg.exe`。可改用其它通知：发邮件、Server 酱、企业微信 / 钉钉机器人，或直接读 `login-state.json` 做个小网页。

**Q14：AstrBot 没被自动拉起来？**
- AstrBot 由 `scripts/astrbot_watchdog.ps1` 独立看护（**普通权限**运行），不由 guardian 启动。
- 检查脚本里的 `$ASTRBOT_DIR` 下是否有 `main.py`、`$PYTHON` 是否正确；进目录手动 `python main.py` 先解决它自身的报错。

**Q15：关掉控制台窗口，机器人就死了？**
- v2 的所有拉起动作都用 `CreateNoWindow`，窗口根本不会出现，关窗口也就谈不上"连带杀死"。
- 如果你还看到残留窗口，多半是旧版脚本用 `Start-Process cmd -WindowStyle Minimized` 起的进程，换新版并重启任务即可。

## 网络与账号

**Q16：用 WiFi 还是网线？**
- 长期挂机强烈建议**网线**；WiFi 的省电、干扰、漫游都会造成短暂断流。

**Q17：network_fix.ps1 执行后网络断了？**
- 脚本会重启网卡，断网几秒到十几秒属正常，会自动恢复。

**Q18：频繁被 `KickedOffLine` 踢下线怎么办？**
- 先排除**同号多端在线**：手机 QQ 的「切换账号」**不等于退出登录**，小号会话仍在后台，服务端会认为 PC 侧"登录态已失效"。用完请在小号界面**退出登录**。
- 其次保持 NapCat 为新版、QQ 为官方推荐版本（老 NapCat 会被判为外挂强制下线）。
- 开通会员**不能**防风控；风控看设备指纹、登录地、行为模式。
- 别把保活间隔调得太短，也不要让守护脚本反复重启。

**Q19：桌面 QQ 一开，机器人就掉？**
- 两者共用 `%APPDATA%\QQ`，Electron 单实例锁互踢。设置 `$QQ_DATA_DIR`（即 `NAPCAT_QQ_DATA_DIR`）隔离数据目录，代价是切换时扫码一次。

## 安全

**Q20：把配置发到 GitHub 会不会泄露信息？**
- 仓库里的示例都是**脱敏占位**，没有真实 QQ 号 / 密钥。新版的 `guardian.ps1` 也已把 `$QQ_UIN`、`$WEBUI_TOK` 换成 `YOUR_BOT_QQ` / `YOUR_WEBUI_TOKEN`。
- 你自己的脚本与 `cmd_config.json` 含真实信息，**不要直接提交**；建议用 `.gitignore` 排除，或只提交 `.example` 版本。

**Q21：本地 API 要对外暴露吗？**
- 不要。本地 API 绑定 `127.0.0.1` 即可，否则可能被他人调用。

## 其它

**Q22：如何查看守护日志？**
- 查看 `guardian.ps1` 里 `$LOG_FILE` 指向的文件，默认 `D:\napcat\guardian.log`。

**Q23：如何彻底停止守护？**
```powershell
Unregister-ScheduledTask -TaskName NapCatGuardian -Confirm:$false
```
