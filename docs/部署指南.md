# 部署指南（小白版）

本指南假设你已经能让 NapCat + AstrBot 正常跑起来（扫码登录、机器人能回消息），只是想让它"挂得稳、被踢了能自愈、开机不用管"。

---

## 一、准备工作

### 1. 确认目录结构

以本方案为例（路径可以不同，但建议纯英文、无空格）：

```
D:\napcat\NapCat.Shell\                        # NapCat 程序目录
C:\Users\你的用户名\qq-deepseek-bot\astrbot\   # AstrBot 目录
D:\napcat-guardian\                            # 本仓库（守护脚本）
```

### 2. 确认 NapCat 已开启本地 HTTP API

守护脚本通过本地 HTTP API（默认 `http://127.0.0.1:3000`）发保活、查状态。

把 `config/napcat/onebot11.example.json` 复制到 NapCat 的 `config/` 目录，改名为：

```
onebot11_<你的机器人QQ号>.json
```

里面包含：

- 一个 HTTP Server（`127.0.0.1:3000`）；
- 一个反向 WebSocket 客户端，连到 AstrBot（`ws://127.0.0.1:6199/ws`）。

重启 NapCat 后，访问 `http://127.0.0.1:3000/get_status` 应能返回数据。

### 3. 打开 NapCat 的文件日志

`config/napcat_<你的机器人QQ>.json` 里把 `"fileLog"` 设为 `true`（`fileLogLevel` 用 `info` 就够）。

> 为什么必须开：v2 的"发送失败探测"要读 NapCat 自己的日志（`<NapCat目录>\logs\*.log`）来判断长连接是否已死。不开也能跑，但会退化成只看 `get_status`，而它可能假在线几十分钟。

### 4. 拿到 NapCat WebUI token

打开 NapCat 的 `config/webui.json`，找到：

```json
"token": "xxxxxxxx"
```

守护脚本用它做快速登录 / 重启 worker，先记下来。

---

## 二、配置守护脚本

打开 `scripts/guardian.ps1`，找到顶部 `Configuration` 区：

```powershell
$QQ_UIN     = "YOUR_BOT_QQ"            # ← 改成机器人 QQ 号
$HTTP_API   = "http://127.0.0.1:3000"  # 本地 OneBot HTTP API
$WEBUI_API  = "http://127.0.0.1:6099"  # NapCat WebUI
$WEBUI_TOK  = "YOUR_WEBUI_TOKEN"       # ← 改成上一步拿到的 token
$NAPCAT_DIR = "D:\napcat\NapCat.Shell" # ← 改成你的 NapCat 目录
$LOG_FILE   = "D:\napcat\guardian.log"
$QR_FILE    = "D:\napcat\NapCat.Shell\cache\qrcode.png"
$STATE_FILE = "D:\napcat\qrsync\login-state.json"   # 可选，给网页/通知读
$QQ_DATA_DIR = "D:\napcat\qqdata"      # ← 想和桌面 QQ 共存就填，留空则共用数据目录
```

其余保持默认即可。**改完务必确认文件存为 "UTF-8 with BOM"**（记事本"另存为 → 编码：UTF-8 带 BOM"），否则 PowerShell 5.1 解析中文会报语法错误。

> 关于 `$QQ_DATA_DIR`：填了之后机器人拥有独立的 QQ 数据目录，桌面 QQ 登大号也不会互踢；代价是**切换的那一刻需要重新扫码一次**。

## 三、安装为计划任务

**右键** `scripts/install_guardian.bat` → **以管理员身份运行**。

它会自动提权并调用 `install_guardian.ps1`，完成：

1. 注册计划任务 `NapCatGuardian`；
2. 设置为：登录时启动、最高权限、隐藏窗口、失败自动重启；
3. 立即启动。

看到 `Install complete. Guardian is running ...` 即成功。

### 验证

```powershell
Get-ScheduledTask -TaskName NapCatGuardian
```

`State` 应为 `Running`。等一个保活周期（30–45 分钟）后看 `guardian.log`：

```
keep-alive sent: 21:10  check
```

说明保活已在工作。

---

## 四、（可选）看护 AstrBot

AstrBot **不由 guardian 启动**（guardian 是最高权限，而 AstrBot 装了"电脑操控"类插件，跑在管理员上下文里风险太大）。用独立脚本以**普通权限**看护：

1. 编辑 `scripts/astrbot_watchdog.ps1`：

```powershell
$ASTRBOT_DIR   = 'C:\Users\你的用户名\qq-deepseek-bot\astrbot'
$PYTHON        = "$env:LOCALAPPDATA\Programs\Python\Python314\python.exe"
```

2. 在普通 PowerShell 里先跑一次确认能起来：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\astrbot_watchdog.ps1
```

3. 开机自启：给它建一个快捷方式放进

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
```

快捷方式目标：

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "D:\napcat-guardian\scripts\astrbot_watchdog.ps1"
```

> 不要用 `.bat`/`.vbs` 包装：杀毒软件（如火绒）可能拦截启动文件夹里的脚本文件，`.lnk` 最稳。

---

## 五、（可选）修复 WiFi 网络

用 WiFi 挂机的话，以管理员身份执行一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\network_fix.ps1
```

它会：

1. 关闭网卡"允许空闲时关闭以省电"；
2. 无线适配器调到最高性能；
3. 重启网卡（**会断网几秒**，属正常现象）。

> 长期挂机最稳的方案是**插网线**。

## 六、验证整体效果

| 检查项 | 期望结果 |
|--------|----------|
| `Get-ScheduledTask NapCatGuardian` | `Running`，`RunLevel` 为 `Highest` |
| `guardian.log` 中 `keep-alive sent` | 每 30–45 分钟一条 |
| 机器人空闲 1 小时 | 仍然在线（保活维持活跃度） |
| 手动 kill 掉 NapCat 的 worker | 守护脚本 20–60 秒内检测到并恢复 |
| 长连接断掉（发消息报 `网络连接异常`） | 日志出现 `send failures detected`，自动重启 worker，**无需扫码** |
| 登录态彻底失效 | 不再反复重启，弹窗 + 写 `login-state.json`，等你扫码 |
| 一小时内连续掉线多次 | 第一次自动恢复，之后进入 120 分钟熔断，日志明确写出原因 |
| 重启电脑后 | NapCat 与 AstrBot 都自动启动、自动上线，且没有控制台窗口弹出 |

---

## 七、卸载

```powershell
Unregister-ScheduledTask -TaskName NapCatGuardian -Confirm:$false
```

AstrBot 看护：删掉启动文件夹里的快捷方式，并结束 `powershell.exe` 中运行 `astrbot_watchdog.ps1` 的那个进程。
